# Argus Project Charter
## 1. 배경과 목적
애플리케이션의 보안 취약점 스캐닝과 정적 분석을 통해 취약점 및 버그를 검출/관리하고 지원 중단된 언어, 프레임워크, 라이브러리를 찾아 수정 단계와 자동/수동 수정 방안을 제시한다.

1차 지원 목표는 Java + Spring을 대상으로 한다.

## 2. 범위
### 2.1 포함

| 기능          | 상세                                                                                  |
| ----------- | ----------------------------------------------------------------------------------- |
| 소스 로드       | - 탐지 대상 애플리케이션의 소스를 로컬 혹은 원격 저장소에서 가져온다.                                            |
| 메타정보 추출     | - 불러온 소스에서 `build.gradle`과 같은 설정 파일을 읽고 애플리케이션의 메타 정보(언어, 프레임워크, 사용 라이브러리 등)를 가져온다. |
| 시크릿 스캐닝     | - 소스 코드 내의 API 키, 토큰, 패스워드 등의 민감정보를 검출한다.                                           |
| CVE 스캐닝     | - 소스 내의 알려진 보안 취약점을 탐지/분석한다.                                                        |
| 정적 분석 수행    | - 정적 분석을 수행해 잠재적인 버그 등을 추출한다.                                                       |
| EOS/EOL 스캐닝 | - 언어, 프레임워크, 라이브러리의 지원 종료 여부를 확인하고 수정 단계 자동/수동 정보 사용자에게 제공한다.                       |
| 통계 정보 제공    | - 보안 취약점, 잠재적인 버그, 언어/프레임워크/라이브러리의 지원 종료 여부 등 탐지한 정보의 통계 정보를 제공한다.                  |
| 버전 관리       | - 애플리케이션의 탐지된 취약점의 비교 추이를 제공한다.                                                     |
| 화면 구성       | - 기능을 표시할 대시보드 화면을 구성한다.                                                            |
### 2.2 제외

| 항목        | 사유                                                   |
| --------- | ---------------------------------------------------- |
| 소스 저장     | 소스는 보안 상의 이유로 별도로 저장하지 않고 로컬, 원격 저장소에서 불러오는 방식으로 한다. |
| 애플리케이션 CI | 대상 애플리케이션 CI는 현재 버전에서 제외한다.                          |
## 3. 제약 조건
- 로컬 환경은 Docker Compose만으로 재현 가능해야 한다.

## 5. 주요 위험

| 위험            | 영향                     | 대응                                                                                                    |
| ------------- | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| 오픈소스에 의존도가 높다 | 오픈소스 선정과 학습에 공수가 소요된다. | 최근(6개월 이내) 커밋 이력이 있는 활발히 관리되고 점유율이 높은 오픈소스를 기준으로 채택하고<br>채택 사유는 ADR 문서 내에 작성한다.<br>필요한 기능만을 선정해 사용한다. |
| 민감 정보를 저장한다.  | 프로젝트가 민감 정보 저장소가 된다.   | 웹에 배포하는 형식이 아닌 설치형으로 제공해 외부에서 접근할 수 없도록 한다.                                                           |
